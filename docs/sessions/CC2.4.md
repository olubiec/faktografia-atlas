# CC2.4 – strona /design ze wszystkimi komponentami + wzorce zrzutów

Kontekst: przeczytaj AGENTS.md, docs/STYL.md i docs/MASTER_PLAN.md (§0 „Wygląd”, §3, §5). Komponenty są gotowe na main: src/components/ui/* (button, input, label, dialog, popover, slider, tabs, toggle-group, tooltip), src/view/ui/* (Icon, SearchField, Sheet), src/view/annotation/* (Annotate). Strony /__test/ui, /__test/interactive, /__test/annotation ZOSTAJĄ (używają ich testy e2e).
Równolegle trwa CC3.2 (dane jednostek) – nie ruszaj src/core, scripts/geo, public/data.
Cel dla użytkownika (właściciel projektu): jedna strona /design, na której widać cały system wyglądu naraz, w trybie jasnym i ciemnym. Na niej oceniamy styl, zanim powstaną ekrany. Zrzuty z tej strony są wzorcem: każda niezamierzona zmiana wyglądu wywala CI.
Zakres: src/view/design/DesignPage.tsx (+ ewentualne małe podkomponenty w src/view/design/), src/App.tsx (TYLKO dopisanie importu i trasy /design), tests/e2e/design.spec.ts, tests/e2e/design.spec.ts-snapshots/*, .github/workflows/update-snapshots.yml, docs/sessions/CC2.4.md.

Warunki odbioru (najpierw testy, potem kod)
1. /design ma sekcje w tej kolejności, każda z nagłówkiem i id: kolory (wszystkie tokeny kolorów z src/styles/tokens.css z nazwą i wartością), typografia (cała skala z STYL.md §3, liczby w kroju mono), logo (pliki z public/brand/: logo granat/jasne, znak granat/jasny, favicon – każdy na właściwym tle), przyciski, pola (Input, Label, SearchField), ikony, zakladki, dymek, okno (Dialog), popover, suwak, przelacznik (ToggleGroup), arkusz (Sheet), zakreslenia (wszystkie 4 typy Annotate, ale na ekranie widoczne jest najwyżej jedno naraz – przełączane przyciskiem, zgodnie z STYL.md §7).
2. Strona używa wyłącznie istniejących komponentów i tokenów. Zakazane: kolory hex w src/view/**, shadow-*, rounded-* (poza rounded-none), backdrop-blur, ikony spoza iconoir-react. (Istniejący test tests/unit/ui-scan.test.ts i view.test.ts muszą dalej przechodzić.)
3. Test e2e: każda sekcja z warunku 1 jest widoczna; axe bez naruszeń w trybie jasnym i ciemnym; przełącznik motywu działa; na telefonie (390×844) brak poziomego przewijania.
4. Wzorce zrzutów: test toHaveScreenshot dla /design – 4 warianty (1440×900 i 390×844, jasny i ciemny), fullPage: true, animacje wyłączone (animations: 'disabled'), zakreślenia w stanie końcowym. Test zrzutów uruchamia się tylko, gdy process.env.CI (lokalnie test.skip), bo wzorce muszą powstać w tym samym obrazie Dockera co CI.
5. .github/workflows/update-snapshots.yml: ręczne uruchomienie (workflow_dispatch z polem branch), kontener mcr.microsoft.com/playwright:v1.64.1-jammy (jak w ci.yml), pnpm install --frozen-lockfile, pnpm build, pnpm exec playwright test tests/e2e/design.spec.ts --update-snapshots, commit zmienionych plików *-snapshots/* na podaną gałąź (permissions: contents: write). W PR opisz właścicielowi jednym zdaniem, gdzie kliknąć, żeby wygenerować wzorce (Actions → Update snapshots → Run workflow → nazwa gałęzi).
6. Zrzuty z pnpm shots dla /design (jasny/ciemny, komputer/telefon) w opisie PR.
