## R11.1 – `aws s3 sync` z R2 i sumy kontrolne w AWS CLI v2

**Wynik skrócony:**
- Dokumentacja R2 podaje użycie AWS CLI z `--endpoint-url https://<ACCOUNT_ID>.r2.cloudflarestorage.com` i regionem `auto`, ale pokazuje tylko `s3api list-buckets`, `s3api list-objects-v2` i `s3 presign`. **`aws s3 sync` w dokumentacji R2: brak wzmianki.**
- Znany problem istnieje: od końca 2024 r. AWS SDK i CLI domyślnie wysyłają sumy kontrolne, których R2 nie obsługiwał (komunikat „not implemented”). Obejście: `WHEN_REQUIRED` dla obu ustawień sum kontrolnych.
- Czy **dziś** (stan R2 październik 2026) domyślne ustawienia CLI v2 działają z R2 bez obejścia: **NIEZWERYFIKOWANE** (nie testowałem; dokumentacja R2 tego nie rozstrzyga).

## R11.2 – Publiczny kubełek R2: CORS i kompresja `.json`

**Wynik skrócony:**
- **CORS:** TAK, da się ustawić (panel, Wrangler; strona S3 API wymienia też Get/Put/DeleteBucketCors). Dla **własnej domeny** dokumentacja wprost mówi, że nagłówki CORS są zwracane automatycznie przy ustawionej polityce. Dla **`r2.dev`** dokumentacja CORS **nie wspomina** tego adresu → NIEZWERYFIKOWANE wprost.
- **Kompresja:** wpis w notatkach wydań z 16.03.2023: publiczne kubełki zwracają `Content-Encoding` dla plików gzip, gdy żądanie ma `Accept-Encoding: gzip`. Czy R2 **sam kompresuje** pliki: dokumentacja tego nie mówi. Własna domena: Cloudflare ma ogólną kompresję odpowiedzi (w tym `application/json`), ale strona o niej nie wspomina R2.

### Przykład konfiguracji z dokumentacji (strona CORS, 23.09.2026)
Plik dla Wranglera (GET z jednego źródła):
```json
{
  "rules": [
    {
      "allowed": {
        "origins": ["https://example.com"],
        "methods": ["GET"]
      }
    }
  ]
}
```
Format panelu (GET z lokalnego serwera):
```json
[
  {
    "AllowedOrigins": ["http://localhost:3000"],
    "AllowedMethods": ["GET"]
  }
]
```

## Czego nie ustaliłem

- Czy `aws s3 sync` z R2 działa **dziś** z domyślnymi ustawieniami AWS CLI v2 (bez `WHEN_REQUIRED`) – nie testowałem na R2; dokumentacja R2 nie ma przykładu `sync`.
- Czy poprawka Cloudflare z 03.02.2025 usunęła potrzebę obejścia dla CLI v2; co dokładnie naprawiono; czy PutObject przyjmuje dziś nagłówki `x-amz-checksum-*` (odczyt strony S3 API przez streszczenie wskazał, że ich nie wymienia).
- Zgłoszeń w `github.com/aws/aws-cli/issues` dotyczących wprost R2 (lista zgłoszeń nie otworzyła się; poza #9214 nie otwierałem innych numerów).
- Daty wydania AWS CLI 2.23.0 (surowy `CHANGELOG.rst` zablokowany dla odczytu) i aktualnej wersji CLI.
- Czy polityka CORS działa na adresie `r2.dev` (dokumentacja milczy, wątek z forum nie rozstrzyga).
- Czy R2 sam kompresuje pliki (gzip/brotli), czy tylko serwuje to, co zapisano z `Content-Encoding`; czy kompresja z Compression Rules dotyczy odpowiedzi z kubełka na własnej domenie.
- Dokładnego przypisania operacji do klasy A i B w cenniku R2.
- Dat postów w wątku forum o v3.729.0 (wątek ich nie pokazał).
